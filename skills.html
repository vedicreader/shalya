skills

Instructions an agent reads when it needs them, and extensions a user can drop in.

A skill

Skills come from two sources. A pyskill is a Python module whose docstring is the skill, published by an installed package (see pyskills). A SKILL.md file is a markdown file in a skills folder, in the Agent Skills layout. Both become a Skill, with a name, a source, a description, and where it came from so a person can go and read it.

A Skill holds a loader for its body, not the body, so finding skills does not read every file. When no description is given, it is the body’s first paragraph on one line.

GROUP is the entry-point group installed packages publish pyskills under. EXTRA_MODULES lists modules that are skills but do not publish one. MAX_SKILL_CHARS caps the length of a skill body sent to the model.

GROUP, EXTRA_MODULES, MAX_SKILL_CHARS
('pyskills', ('exhash.skill',), 20000)
test_eq(GROUP, 'pyskills')
test_eq(EXTRA_MODULES, ('exhash.skill',))
test_eq(MAX_SKILL_CHARS, 20_000)

Where skills come from

Installed packages publish pyskills under the pyskills entry-point group. A module’s description comes from its docstring, and Python offers no way to read a docstring without importing the module, so discovery imports each pyskill module once. A module with an empty docstring is skipped.

SKILL.md files are looked for in a list of folders, from lowest to highest precedence, so that a later folder’s skill replaces an earlier one with the same name. skill_dirs returns the list. It starts with the skills folder inside learned, for skills a tool wrote rather than a person, then the application’s config folder cfg, then ~/.agents/skills for a person’s own skills, then .leela/skills and .agents/skills in each project root. A project can therefore replace what a person set up for themselves, and a skill a tool learned replaces an installed pyskill but loses to every folder a person writes.

The read_skill tool reads the same installed skill that discovery found through the pyskills entry point:

from shalya.host import LocalHost
from shalya.skills import discover
from shalya.tools import skill_tools
installed_skills = discover()
installed_host = LocalHost(index=False)
installed_read = {t.__name__: t for t in skill_tools(installed_host, lambda: installed_skills)}['read_skill']
installed_exhash = next(s for s in installed_skills if s.where == 'exhash.skill')
installed_body = installed_read(installed_exhash.name)
assert installed_body.startswith(f'<skill name="{installed_exhash.name}"')
assert len(installed_body) > 100 and 'exhash' in installed_body.lower()

The index

skill_index renders the block that goes into the system prompt: a heading, a line telling the agent to call read_skill(name) before doing the work a skill covers, and one line per skill with its name and description, never its body. Each description is cut to SKILL_DESC_MAX characters at a word boundary, so one long description cannot crowd out the rest.

find looks a skill up by exact name, then by unique prefix, then by unique substring. A name that matches several skills returns None instead of guessing, and the read_skill tool then lists the skills that exist.

find(skills, 'notebook-tests').name, find(skills, 'notebook').name, find(skills, 'nope')

test_eq(find(skills, 'notebook-tests').name, 'notebook-tests')
test_eq(find(skills, 'notebook').name, 'notebook-tests')     # unique prefix
test_eq(find(skills, 'tests').name, 'notebook-tests')        # unique substring
test_eq(find(skills, 'nope'), None)

test_eq(find(two, 'edi'), None)                              # ambiguous prefix

Extensions

An extension is a Python file a user drops in an extensions folder. It defines setup(reg), and through reg, a Registry, it may add tools, skills and slash commands, hook lifecycle events, and replace the approval policy. That is all a Registry offers: it gives an extension no access to the model, the engine or the conversation history.

EVENTS lists the lifecycle events an extension may hook, such as before_tool and after_turn. Hooking any other name raises an error, so a typo cannot silently hook nothing.

EVENTS
('before_turn',
 'after_turn',
 'before_tool',
 'after_tool',
 'compact',
 'approval')
test_eq(EVENTS, ('session_start', 'before_turn', 'after_turn', 'before_tool', 'after_tool', 'stop', 'compact', 'approval', 'background_done', 'watch', 'session_end'))
test_eq(len(set(EVENTS)), len(EVENTS))

shell_hooks

def shell_hooks(
    reg, path
):

Register the hooks a hooks.json lists: [{event, match, command}].

load(reg, roots=(), cfg=None, project=False, paths=(), only=None) discovers ramabana.mods entry points, then configuration extensions and mods, then project .leela/extensions and .leela/mods when project=True, then explicit paths. A later source replaces an earlier source with the same name before setup runs. Names starting with _ or . are skipped. A folder mod contains mod.py, optional mod.toml metadata, and optional skills/NAME/SKILL.md files. reg.mods holds records with name, source, on, and note. reg.notes keeps load and failure lines. <cfg>/hooks.json still registers shell hooks through shell_hooks.

reg.mod and reg.home identify the owning mod during setup and inside its callbacks, commands and tools. Tool wrappers preserve names, signatures, docstrings and annotations. The registry does not create the home folder. Explicit file mods outside mods or extensions use <cfg>/mods/NAME when cfg is set. Without cfg, they use path.parent/NAME. When only is a collection of names, other mods remain off with the note not in this vesha. Their modules do not run until on_mod(name) enables them. off(name) removes that mod’s registrations and cancels its timers. on_mod(name) runs setup again. Unknown names raise KeyError with the known names. drop_loaded() removes the loaded mods but keeps registrations made outside the load.

reg.status_segments contains guarded callables taking an agent. reg.bands contains guarded callables taking a view, each with a rows limit. The frontend supplies the view fields agent, busy, t, width, and rows. drain_notices() returns dictionaries with mod and text. It clears the queue. on_redraw is a frontend callback and must be safe to call from worker threads. Registry hooks and timers retain their mod identity for notices and new registrations. reg.thread(fn, *args, **kw) starts a daemon thread with the calling mod’s context. Registrations and notices from it belong to that mod. Plain threading.Thread loses ownership; its notices have mod=None. One-shot timers remove their registry entries when they finish. Failed repeating timers and cancelled timers remove their entries too.

reg.store(default=None) returns the calling mod’s JSON store. store.data loads a dictionary from <home>/state.json on first access. A missing or unreadable file uses default or {}. store.save() creates the folder and writes atomically through a temporary file beside the target. store.update(fn) takes an exclusive lock on <home>/state.lock, re-reads the file, calls fn(data), saves and returns the data. A mod without a home uses memory only.

check(path) returns a dictionary containing tools, commands, skills, hooks counts by event, status, bands row limits, timers intervals and repeat flags, and mods records. tool_docs adds each tool’s name, signature and doc. It runs setup but starts no registry timers or registry threads. It is not a sandbox for arbitrary Python side effects.

A hook may return a value. fire(event, ...) runs the event’s hooks in registration order and returns their return values, so a before_tool hook can return a reason to deny the call or replacement arguments, and an after_tool hook a rewritten result. each(event) returns live (mod_name_or_None, callable) pairs in registration order. Each callable uses the same failure rules as fire. Mod hooks on before_tool and before_turn fail closed with mod NAME failed: <error> and run again on the next event. A failing mod approval policy returns deny. These decision callbacks record each distinct error once. Other failing mod hooks, status segments, bands and timers are recorded once and skipped on later calls. Hooks without a mod owner record every failure and run again next time. SystemExit during module loading or setup disables the mod. KeyboardInterrupt propagates. load records its registration span even when interrupted. Already-running calls are not interrupted. Re-enabling a mod creates fresh registrations. A shell hook is a command listed in hooks.json as {event, match, command}, where match is a glob on the tool name. It receives the event as JSON on standard input and may answer with a JSON object on standard output holding deny, args or result. Anything else it prints is ignored.

Reloading re-reads the extension files, and must not throw away what the running program registered since. load records which registrations came from the files (mark and mark_loaded), and drop_loaded removes exactly those and keeps the rest. loaded says whether the files are currently loaded.

live = load(Registry(), cfg=tmp)
def live_tool(x: str) -> str: return x
live.tool(live_tool); live.command('mine', lambda a, arg: arg); live.on('after_tool', print)
live.drop_loaded()
[t.__name__ for t in live.tools], list(live.commands), len(live.hooks['after_tool']), live.loaded
test_eq([t.__name__ for t in live.tools], ['live_tool'])   # the file's word_count went, mine stayed
test_eq(list(live.commands), ['mine'])
test_eq(len(live.hooks['after_tool']), 1)
test_eq([s.name for s in live.skills], [])
test_eq(live.loaded, False)
load(live, cfg=tmp)                                       # the files come back on the next read
test_eq([t.__name__ for t in live.tools], ['live_tool', 'word_count'])
live.drop_loaded()                                        # and a second round is not lossy
test_eq([t.__name__ for t in live.tools], ['live_tool'])
test_eq(Registry().drop_loaded().tools, [])               # never loaded: nothing to take back

session_end hooks run when the host closes the session. Status segments and bands return frontend data. Registry.status_texts(agent) returns nonempty status strings in registration order. A nested call on the same thread returns no segments. A failed segment does not prevent later segments from running. Notices drain once.

Registry.section(title, fn) adds a section to the side pane. title must be a string. fn(agent) returns a list of strings, one string for each row. Registry.section_rows(agent) returns a dict with title and rows for each section, in registration order. A row that is not a string is left out. A section with no string rows is left out.

Use Registry.add_mod(name, setup, home=None) to unit-test a mod without writing a mod file. It runs setup(reg) with the same ownership and callback context as a loaded mod. It returns the mod record. Pass home for a persistent store. Without home, the store stays in memory.

store.data returns the default when state.json cannot be read or parsed as a JSON object. store.problem holds the reason after a read and is empty when the read succeeds or the file is absent. store.save() and store.update(fn) raise ValueError naming the file while it has a problem. Repair or remove the file, then call store.reload() to re-read it and clear the problem.

def setup_example(reg):

    reg.status(lambda agent: 'ready')
    reg.band(lambda view: ['one row'], rows=2)

    reg.section('Quiet', lambda agent: [])
