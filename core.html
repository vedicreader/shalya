core

What every tool result looks like, and the limits it is held to.

Limits

Tool results use up the model’s context window, so each kind of result has a cap. MAX_TOOL_CHARS caps one result, and is sized for the smallest model in use. Tool factories take the cap as mx, so a harness running a larger model can raise it. MAX_HITS caps search hits, MAX_GREP_HITS exact grep matches, MAX_API the names a public_api listing returns, and MAX_FILE the size of a file worth reading as source at all.

# a grep answers with more rows than a search, because an exact match is cheaper to read
assert MAX_GREP_HITS > MAX_HITS
assert MAX_TOOL_CHARS < 8_000 and MAX_FILE > MAX_TOOL_CHARS
test_eq((MAX_TOOL_CHARS, MAX_HITS, MAX_GREP_HITS, MAX_API, MAX_FILE), (6000, 20, 60, 200, 2_000_000))

Every search backend returns its results as Hits: the path, line, symbol and matching text.

Failure

A tool must not raise, because an exception ends the agent’s turn. A tool that fails returns a string starting with ERROR: instead, so the model can read what went wrong and try again. err builds that string, failed checks for it, and host_err formats an exception as Type: message. HostError is the exception a host raises to refuse something.

attempt(what, f) is the try/except every tool would otherwise repeat. It runs f and turns any exception into an err, except NotImplementedError, which it lets through: that means the host cannot do this at all, which the caller handles differently from a call that failed. Media is a result string that also carries pictures, as paths or bytes, which the agent’s loop sends to the model after the text.

The read guard

An application may need to control what reaches the model, for example to keep personal data away from a hosted model while letting a local one see it. A host’s read_guard, when set, is a function every read tool calls before sending content. It receives a ReadCheck describing the read: the path (a URL or page id for web reads), the tool, the kind of content (text, hits, cell, diff, url, page or image), the turn’s model, whether that model runs locally, and text, the content the tool would send. text is loaded only if the guard asks for it, so a guard that decides by path reads nothing. local is None when the host cannot tell, and a guard should then treat the model as hosted.

The guard returns None or True to send the content unchanged, a string to send instead (a masked version, or even an empty string), or a Refusal; False is a refusal with the default wording. A guard that raises refuses the read with kind guard_failed. A refusal reaches the model as an ERROR: result naming its kind, path and reason, so failed recognises it. model and local come from the host’s model_local(), which returns (local, model).

Tools call the guard through two helpers. guard_read returns None (send as is), a replacement string, or a Refusal. screened returns the text to send, or the Refusal. With no guard set, guard_read returns None without calling anything and screened returns the text unchanged.

The sandbox

The sandbox keeps tools inside the folders the user opened, called roots. Each path is resolved before it is checked, so .., ~ and symbolic links are judged by where they actually lead. Sandbox does this and raises Unsafe, a HostError, for a path it refuses. Each host keeps one Sandbox and every tool goes through it.

Some paths are refused even when reads outside the roots are allowed. DENY lists them: SSH and cloud credentials, .env files, private keys and similar. denied checks a path against that list, ignoring case, because a case-insensitive disk opens .SSH as .ssh.

spill_dir

def spill_dir():

The private folder, one per process, where results too long to send whole are saved; every Sandbox may read it and none may write it.

Sandbox(roots) opens folders for reading and writing, and read_roots folders for reading only. check(path) resolves a path, relative to the first root if it is relative, and returns it or raises Unsafe. A path that does not exist yet still resolves, since a tool creating a file needs that; readers pass must_exist=True. reading=True marks a read, which may use read-only roots and read_outside. covers and reads test a path against the two kinds of root, add_root and drop_root open and close folders, root_of names the root holding a path, and bare and under handle a file name given by a person or a model.

A result too long to send whole can be saved with spill, which writes it to the folder spill_dir names and returns the path. Every sandbox may read that folder, so the model can page through the full result with view_file, and none may write to it.

tmp = TemporaryDirectory()
root = Path(tmp.name).resolve()/'proj'
(root/'pkg').mkdir(parents=True)
(root/'pkg'/'a.py').write_text('x = 1\n')

sb = Sandbox([root])
sb.check('pkg/a.py').name, sb.check('pkg/new.py').name, sb.covers(root/'pkg'), sb.root_of('pkg/a.py') == root

Resolving before checking is what stops a symbolic link from escaping: checking the unresolved path would accept link/secret.txt because it looks inside the root. With no open folders nothing resolves, so a host cannot be tricked into reading /etc/passwd.

outside = Path(tmp.name).resolve()/'outside'
outside.mkdir()
(outside/'secret.txt').write_text('token\n')
(root/'link').symlink_to(outside, target_is_directory=True)

test_fail(lambda: sb.check('link/secret.txt'), contains=SANDBOX)        # a symlink out
test_fail(lambda: sb.check('../outside/secret.txt'), contains=SANDBOX)  # .. traversal
test_fail(lambda: sb.check(outside/'secret.txt'), contains=SANDBOX)     # an absolute path elsewhere
test_fail(lambda: sb.check('pkg/new.py', must_exist=True), contains='no such file')
test_fail(lambda: Sandbox().check('/etc/passwd'), contains=NO_ROOTS)    # nothing open, nothing readable

read_outside=True widens reads only. Writes must still land in an open folder, and credential paths are always refused.

lax = Sandbox([root], read_outside=True)
lax.check(outside/'secret.txt', reading=True).name

Open folders never nest. Opening a parent closes the roots inside it, and opening a folder already covered changes nothing, so each file is walked and indexed once.

sb2 = Sandbox([root/'pkg', root])                         # a folder and its parent, opened together
[r.name for r in sb2.roots]

bare refuses a name that is really a path, such as ../../etc. under places a named entry inside a folder without letting it escape.

sb.under('pkg', 'b.py').name, sb.bare('b.py')

Clipping

Long results have to be cut to fit the budget, and the cut should tell the model what it missed. clip shortens a string to n characters, at a line break when one is close, and appends a note giving how much was shown. The note counts against n. more adds a hint on how to read the rest, and keep=True saves the whole result with spill and names the file in the note. clip_json does the same for JSON while keeping it valid JSON: a list keeps the items that fit plus a last item saying how many more there are, and a dict keeps its plain fields, with the longest strings shortened and a truncated note.

clip_lines renders a list of lines within n characters and says which line to continue from, which is how view_file pages through a file. more is the hint, and {next} in it is replaced by the next line number. empty is returned for an empty list. A single line longer than the budget is cut by characters, and the note gives its length but no line to resume from.

Edits

A model sends edits as lists, because the tool schemas declare them as arrays, and a harness may pass a stray JSON string through. cmds parses commands for exhash, the hash-addressed editor, into the tuples it expects. edits parses exact-text replacements. Both reject input they cannot read with an error that names the shape wanted.

source

cmds

def cmds(
    commands
):

Parse exhash commands, as JSON or lists, into the tuples exhash expects, nested lists included.

cmds('[["12|a1b2|", "s", "old", "new"], ["30|9f3c|", "a", "appended"]]')
test_eq(cmds([['1|ab|', 'd']]), [('1|ab|', 'd')])
test_fail(lambda: cmds('{"not": "a list"}'), contains='must be a JSON list')
test_fail(lambda: cmds('["bare string"]'), contains='must be an array')

edits accepts a list of {oldText, newText} dicts, a list of [old, new] pairs, or a single dict. A JSON string of any of those is still accepted in this release. apply_edits applies them to a text. Each oldText must appear exactly once, and the edits must not overlap. Otherwise it raises a ValueError naming the edit and how to fix it: give the exact text, add surrounding lines when a match is ambiguous, or merge overlapping edits.

Which tools write

An application usually asks a person before a tool changes something. @writes marks a tool as one that does, and is_write checks the mark. WRITE_TOOLS lists the same tools by name, for a caller that only has a name; the tests check that the two agree. @acts and has_effect mark tools that act without writing a file the user owns, such as running an API call or starting a watch, and ACTING_TOOLS names them. Approval does not gate these, but a sub-agent told not to act loses them too. The git tools are listed in GIT_READ_TOOLS and GIT_WRITE_TOOLS.

@summary attaches a function that turns a call’s arguments into the one line a person reads after the tool runs, such as “Edit pkg/a.py”. summarise produces that line for a tool or a bare tool name, falling back to name(arg=value, ...). It finds summaries for bare names in SUMMARIES, which shalya.tools fills when it is imported. one_line squeezes any value onto one short line.
